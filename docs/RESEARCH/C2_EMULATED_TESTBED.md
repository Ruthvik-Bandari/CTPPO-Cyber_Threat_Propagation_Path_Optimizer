# C2 — Emulated multi-host testbed (ground-truth attack paths)

_Generated by `evaluation/emulated_testbed.py` (no Docker required)._

A live container/VM testbed is heavy infra; this is the runnable counterpart. We hand-specify
realistic multi-host networks (DMZ / app / data tiers, redundant routes, a high-CVSS dead end,
multi-goal) where the **ground-truth exploitable attack paths are known by construction** — the
entry→goal simple paths over the exploit edges, enumerated independently of the engine. We then
validate the NAMOA* Pareto front against that ground truth.

- **Goal coverage = 0.900** (mean): the front reaches every reachable crown jewel in the
  single-goal networks, but only one of two in `two_crown_jewels`.

## Honest finding: multi-goal coverage

`two_crown_jewels` exposes a real behavior, not a bug: NAMOA* returns the **global** Pareto
front across *all* goals. When one goal's best path dominates another goal's best path on all
three objectives (here `internet→dmz→billing` vs `internet→dmz→hr`), the dominated goal's path
is correctly pruned — so the global front can omit a path to a reachable crown jewel.

**Mitigation:** for networks with multiple crown jewels, run a **per-goal query** (one goal
marked at a time) and union the fronts to guarantee each jewel has at least one surfaced path.
This is a usage recommendation for multi-goal deployments and a candidate engine option
(per-goal Pareto fronts) for future work.

## Reading
On controlled ground-truth networks the engine is **sound** (no spurious paths) and compresses
the exploitable-path space to a small non-dominated front, while the multi-goal case documents a
concrete, honest limitation with a clear mitigation. This complements the real-data path
recovery in [`C2_PATH_RECOVERY.md`](C2_PATH_RECOVERY.md); a live container/VM emulation remains
future work for an end-to-end generalization claim.
